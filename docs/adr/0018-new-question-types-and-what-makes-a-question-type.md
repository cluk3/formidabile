# ADR-018: Nine new question types, and what makes something a question type

- **Status:** Accepted
- **Date:** 2026-10-22

A question type fixes the answer representation and the kind of value accepted. A constraint narrows that value: a length, a range, a selection count, date bounds, a step, or "must be yes". A display setting changes only the control. Only a change of question type needs a new question identity (ADR-005), so this line decides what an editor can change on a published question without splitting its analytics (ADR-009).

This iteration adds nine question types: phone, URL, time of day, date and time, date range, ranking, single-choice matrix, multiple-choice matrix and address. It also adds four displays on number (rating, scale, slider and NPS), a step constraint on number, and a "must be yes" constraint on boolean. They ship in the same major `info.version` bump as pages and conditions (ADR-017), at definition format 2. Formats 1 and 2 accept the same list of question types. The research is in `.scratch/form-builder-iteration/research/question-types.md` and `validation-rules.md`.

This amends ADR-002 (the seven question types), ADR-005 (the answer union), ADR-009 (the analytics bases for ranking, matrix and NPS), ADR-010 (the advisory answer schema) and ADR-017 (the operators for these types).

The calls a reader is most likely to "fix" by mistake:

- **Phone and URL are question types, and rating isn't.** Email set the precedent: a string with its own check is its own type. If phone were a setting on text, a free-text question could become a phone question under the same identity, and combined analytics would mix the two. A rating, a scale, a slider and NPS all store the same integer as a number question, so the control is only a display setting.
- **The answer union gains one arm: an object whose values are strings or lists of strings.** Matrix, date range and address answers use it. A date range is `{ start, end }`, not a two-item list, because the union is untagged and a list's order would carry meaning that nothing in its shape states. A ranking reuses the existing list of strings.
- **Phone is stored in E.164, with no default country.** The answer is `+` followed by at most 15 digits, and the respondent must type a country code. Shared core code strips spaces, dashes, dots and parentheses before checking, in the browser and on the server. Turning a local number into an international one needs per-country rules (the UK drops the leading 0, Italy keeps it), which would add tens of KB of metadata to the renderer. The operators are equals, does not equal, starts with and does not start with, so a condition can route on a country code.
- **A URL is stored as typed.** It must be `http` or `https`, parse with a host, and be at most 2,048 characters. It is trimmed and never normalised. The renderer adds `https://` where the respondent can see it when they typed no scheme. The builder shows a URL answer as plain text, never as a link, because a link a respondent supplies and an admin clicks is a phishing route. The operators are the text operators.
- **Time of day, and date and time, carry no time zone.** A time is `HH:MM` on a 24-hour clock, and a date and time is the local wall-clock `YYYY-MM-DDTHH:MM`, neither with seconds, so both compare as strings, like dates. They mean "this time, where the question is about", not one instant, and the respondent's time zone is not recorded. Both have optional earliest and latest bounds. Publish rejects an earliest bound after the latest, so a time window can't cross midnight. The operators are is at, is before and is after.
- **A date range is both dates or neither.** The answer is `{ start, end }` in `YYYY-MM-DD`, with start on or before end, so a single day is allowed. Both dates must fall inside the question's bounds. The operators are starts before, starts on, starts after, ends before, ends on and ends after. The control is two native date inputs, labelled From and To, in one group.
- **A ranking starts unranked.** The answer lists every option value exactly once, in rank order, so an optional ranking is complete or absent. A ranking has 2 to 20 options. The respondent adds options to the ranking one by one, and adjusts it with Move up and Move down. A list shown in a default order can't tell "I agree with this order" from "I didn't touch it", for the same reason boolean uses two radios rather than a checkbox. The operators are ranks X in the top N and doesn't rank X in the top N.
- **Single-choice and multiple-choice matrices are two types.** They store different values: one option value per row, or a list of option values per row. A flag would change the answer shape under one identity. Each row has a row value, minted by the builder and stable across versions like an option value, and the columns are ordinary options. A matrix has 1 to 50 rows and at most 12 columns, and needs as many columns as single choice or multiple choice needs options.
- **A required matrix needs every row.** An optional matrix accepts any subset of rows. An unanswered row has no key, and a matrix with no answered row has no answer at all. In a multiple-choice matrix, an answered row has at least one column. There is no per-row required flag and no per-row selection count. A condition names the question and a row. A single-choice matrix row is any of or none of a set of columns. A multiple-choice matrix row includes any of, all of or none of them. Every row also has is answered and is not answered, as does the question as a whole. The renderer shows a table when the element is wide and one group per row when it is narrow, measured on the element's own width, because the host decides how wide it is.
- **An address is six fixed lines.** They are line 1, line 2, city, region, postal code and country. Each question sets every line as shown or hidden and as required or optional, with at least one line shown. The answer holds only the filled lines, each trimmed and at most 200 code points. An optional address with every line empty is unanswered. Once any line is filled, the required lines must be filled too. Country is an ISO 3166-1 alpha-2 code picked from a list, and the renderer names the countries with `Intl.DisplayNames` in the respondent's language, so no list of names ships in the bundle. Postal codes have no per-country format. The operators are is answered, is not answered, and country is any of or none of, which exist only when the country line is shown.
- **Number has one display setting.** It is input (the default), rating, scale, slider or NPS, and changing it keeps the question identity. Publish checks each display:
  - Rating shows stars only, with whole numbers from 1 to a maximum of 3 to 10.
  - Scale has whole numbers from 0 or 1 to a maximum of 2 to 10, with an optional label at each end.
  - Slider needs a minimum, a maximum and a step.
  - NPS is fixed at whole numbers from 0 to 10, with end labels.
- **NPS is a display setting that analytics read.** An NPS question's analytics add the NPS score: the share of promoters (9 or 10) minus the share of detractors (0 to 6), out of answered responses. The score counts only the versions whose snapshot uses the NPS display, and the per-version breakdown shows each version's score. A builder shortcut to a 0 to 10 scale would leave no mark for analytics to find.
- **Step is a constraint on every number question.** It is an optional positive decimal with at most 4 decimal places. A valid answer is the minimum plus a whole number of steps, or a whole multiple of the step when there is no minimum. The check scales both sides to integers, so floating-point error can't refuse a valid value. When only whole numbers are accepted, the step must be a whole number.
- **Rating, scale and slider start empty.** A native slider always has a value, so the renderer's slider shows "Not answered" and no thumb until the respondent first moves it. Every optional question answered with radios gets a "Clear answer" button. That includes the existing single choice and boolean, which had no way back to unanswered.
- **"Must be yes" is the only way to get a checkbox on a boolean.** It makes the question required, so the answer must be yes, on the path (ADR-017). It is shown as one checkbox. Without it, a boolean stays two radios, because an unticked checkbox can't tell No from unanswered.
- **Inputs carry `autocomplete` tokens.** Email has `email`, phone `tel`, URL `url`, and the address lines `address-line1`, `address-line2`, `address-level2`, `address-level1`, `postal-code` and `country`. Text questions have none.
- **Most new types report counts only.** Phone, URL, time of day, date and time, date range and address report answered, skipped and not shown, like text, email and date. These are the exceptions:
  - A ranking reports each option's mean position and how often it was ranked first. The base is the answered responses of the versions that offered the option. It still combines across versions whose option sets differ, as a changed number range does (ADR-009), even though a mean position out of 3 and out of 5 are not on one scale. The per-version breakdown shows the difference.
  - A matrix reports a count and a share for each row and column. The base is the answered rows of the versions that had both that row and that column.
  - Rating, scale and slider use the number summary.
- **The advisory answer schema expresses what JSON Schema can.** That covers the phone and time patterns, a ranking as unique items from the option values with exactly as many items as options, and a matrix as an object with one property per row value. Date-range order, step, and the bounds of a date and time are carried as `x-fb-*` keys, as date bounds already are. The server's check stays final (ADR-010).

## Considered options

- **Phone and URL as formats on text.** Rejected: one identity could then switch between free text and a checked value.
- **Rating, scale and NPS as question types.** Rejected: they store the same integer as number, and switching the control would mint a new identity and split the analytics.
- **One matrix type with a "multiple" flag.** Rejected: the flag would change the answer shape under one identity.
- **A phone-number library with a default country per question.** Rejected: its per-country metadata adds tens of KB to the renderer bundle (ADR-004 weighs the bundle in KB).
- **Date and time as an instant with an offset.** Rejected: it needs the respondent's time zone, and a rule for which zone admins see it in.
- **A ranking that starts in the defined order.** Rejected: an untouched list looks the same as agreement.
- **NPS as a builder shortcut to a scale.** Rejected: nothing in the version would tell analytics to compute the score.
- **A checkbox display on any boolean.** Rejected: an unticked box can't tell No from unanswered.
- **Builder-supplied regular expressions.** Rejected: the pattern runs on the server for every submit, Zod's regex check has no input-length cap, and the products researched agree on no safe subset, so one bad pattern can stall the server (ReDoS).
- **Relative date bounds, such as "within the last 30 days".** Rejected: the set of accepted dates would change every day while the version stays the same, so two responses to one immutable version could be valid under different rules.
- **Deferred:**
  - file upload and signature, which need file storage, a way round the 1 MiB body limit (ADR-015), and an answer that stays readable for superseded versions;
  - picture options on choice questions;
  - checks across answers, which will be named checks such as "on or after question X", never an expression language;
  - custom error messages, which will be a host catalogue keyed by issue code, never text frozen in the version.
